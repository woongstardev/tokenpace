## 1. 한 줄

**tokenpace** — LLM의 초당 토큰 수(tok/s)가 *내 언어로, 내가 읽는 속도에 견줘* 얼마나 빠른지 몸으로 느끼게 하는
정적 웹 페이지. 한국어를 1급 언어로 두되 **영어 사용자도 그대로 쓸 수 있게(i18n) 만든다.**

## 2. 왜 만드나 — 선행 조사 결과 (2026-09-01)

### 2-1. 같은 범주는 이미 포화다

| 사이트 | 특징 |
|---|---|
| https://shir-man.com/tokens-per-second/ | 5/25/67 t/s 프리셋, `?speed=15` URL 파라미터. **TTFT는 명시적으로 제외**한다고 밝힘 |
| https://tokenstead.ai/tokens-per-second | 10/50/100/500 나란히 동시 재생 |
| https://github.com/jimmyboudoux/token-speed-visualizer | 2~4레인 레이스, 1~500 커스텀, **바닐라 HTML/CSS/JS·의존성 0·빌드 없음**, CSP 엄격·외부요청 0. 벽시계 기준 타이밍(누적 드리프트 회피). 파이썬 구문 강조 |
| https://tps-simulator.com/ · https://mikeveerman.github.io/tokenspeed/ · https://float16.cloud/tokenspeed/ · https://nickmimic.github.io/llm-speed-simulator/ · https://kamilstanuch.github.io/LLM-token-generation-simulator/ · https://techtactician.com/llm-tokens-per-second-inference-speed-simulator-tool/ | 대동소이 |

⇒ **"속도만 눈으로 보여주는 것"으로는 신규성 0.** 그 축으로 경쟁하지 마라.

### 2-2. 전부가 비운 세 구멍 = 우리 제품의 존재 이유

1. **언어별 토큰 밀도.** 조사한 전부가 영어 기준이다. 영어는 대략 1토큰 ≈ 4자, 한국어는 1토큰 ≈ 1~2자
   (모델·토크나이저별로 다르다 — **우리가 실측해서 수치를 박는다**). 같은 35 tok/s가 영어로는 초당 ~140자,
   한국어로는 초당 ~35~50자 — **체감이 3배 가까이 갈린다.** 벤치마크의 tok/s 숫자를 한국어 사용자가
   그대로 믿으면 반드시 실망한다. 이 축을 다루는 사이트가 하나도 없다.
2. **TTFT(첫 토큰까지의 대기).** shir-man은 "초기 대기 제외"라고 못박았고 나머지도 안 다룬다. 실제 체감은
   `TTFT + 디코딩 속도`다. 로컬 LLM은 모델 로드·프리필이 크다 — 100 tok/s여도 8초 기다리면 느린 물건이다.
3. **읽기 속도 대비선.** 진짜 판정 기준은 "빠른가"가 아니라 **"내가 읽는 속도를 따라잡는가"**다.
   기준선을 겹쳐 그리면 결론이 판정문으로 바뀐다.

### 2-3. 실측 결과 — v1 의 판정문 예시는 틀렸다 (2026-09-01)

v1 §2-2-3 은 판정문 예시로 *"35 t/s는 한국어 읽기 속도에 아직 못 미친다"* 를 들었다.
**실측해 보니 정반대다.** 정본은 [`docs/token-density.md`](token-density.md) ·
[`docs/reading-speed.md`](reading-speed.md), 재현은 `cd tools && npm ci && npm run all`.

| 실측 | 값 |
|---|---|
| 자/토큰 (o200k_base) | 영어 4.65 · 한국어 1.70 · 일본어 1.33 · 중국어 1.30 |
| 토큰 비율 (영어=1.00, o200k_base) | 한국어 1.39× · 일본어 1.45× · 중국어 1.17× |
| **읽기 속도 환산** | **영어 4.7 tok/s · 한국어 5.4 tok/s** (o200k_base) |
| 토크나이저 전체 범위 | 4.7 ~ 9.0 tok/s |

⇒ **한국어 읽기 속도는 약 5 tok/s 다. 35 tok/s 는 그 7배다.**
그리고 자/초로는 3배 갈리는 한·영이 **tok/s 로 환산하면 겹친다** — 토크나이저가 정보 밀도를
어느 정도 따라가기 때문이다. v1 이 "체감이 3배 갈린다"고 본 것은 *자/초* 축에서는 맞고
*읽기 속도 대비* 축에서는 틀렸다.

**⚠️ v1 의 신규성 근거였던 "한국어는 손해다" 서사가 약해진다.** 손해는 자/초와 API 요금
(1.39×)에서 나지 체감 판정에서 나지 않는다. 이걸 숨기고 원래 서사를 밀면 우리가 비판한
"영어 기준 숫자를 그대로 믿게 만드는" 사이트와 같은 짓이 된다.

### 2-4. 개정된 제품 정의

> **tok/s 가 내 언어에서 실제로 얼마나 빠른지, 내가 읽는 속도에 견줘 재본다.**

**톤은 중립이다** . 사이트가 "속도 경쟁은 무의미하다" 같은 주장을
내세우지 않는다. 실측값과 기준선을 나란히 보여주고 **판단은 사용자가 한다.**
데이터가 충분히 말하므로 주장을 얹을 필요가 없고, 레퍼런스가 목표라면 주장보다 재현 가능한
수치가 오래 간다. 우리가 알아낸 것(읽기 속도 ≈ 5 tok/s)은 결론 문구가 아니라
**화면에서 눈으로 확인되는 사실**로 둔다.

- 축 ③(읽기 속도)이 부록이 아니라 **결론**이 된다
- 축 ②(TTFT)가 그 결론의 증명이 된다 — 체감을 바꾸는 유일한 변수로 남으므로
- 축 ①(언어별 밀도)은 **결론에 도달하기 위한 계산 근거**이자, "당신 언어에서는 얼마인가"라는
  개인화 축으로 남는다. 여전히 아무도 안 하는 것이고, 여전히 우리 것이다
- 포화된 시장에서 "또 하나의 시각화"가 아니라 **반박 가능한 주장 하나**를 들고 나간다.
  반박 가능해야 인용된다

**⚠️ 이 주장의 한계도 같이 실어라** (안 실으면 첫 반박에 무너진다):
- 이건 *읽는* 속도지 *훑는* 속도가 아니다. 코드·표·긴 목록은 눈으로 건너뛰므로 tok/s 가 다시 산다
- 읽기 속도 개인차가 평균을 압도한다 (한국어 출처 SD 가 평균의 63%). 평균은 슬라이더 초기값일 뿐이다
- 출처가 둘 다 안과·심리학 실험이지 "LLM 응답 읽기" 실험이 아니다

## 3. MVP 범위

### 넣는다
- 3레인 동시 스트리밍 기본값 **5 / 10 / 35 tok/s** + 커스텀 슬라이더(1~500)
- **언어 토글 ko / en** — UI 문구·샘플 텍스트·**토큰 밀도**가 함께 바뀐다
- **모델(토크나이저) 선택** — 밀도가 토크나이저마다 2배 가까이 갈리므로(§2-3) 하나로 못 뭉갠다.
  기본은 커밋된 실측 계수, 「정확히 세기」를 누르면 실제 토크나이저를 lazy-load (§4-2)
- 사용자 텍스트 붙여넣기 (자기 프롬프트 결과로 재보게)
- **TTFT 슬라이더(0~10초)** — 각 레인 시작 전 대기. 개정된 제품 정의(§2-4)에서 **핵심 증거**다
- **읽기 속도 기준선** — 레인 위에 겹치는 바 + 판정 문구
- **자기 읽기 속도 측정** — 지문을 띄우고 다 읽으면 누르게 해서 개인값을 얻는다.
  출처 SD 가 평균의 63% 라 인구 평균으로 개인을 판정하는 것은 정직하지 않다. 아무도 안 한다
- **접근성** — `prefers-reduced-motion` 시 스트리밍 대신 정적 타임라인. 본체가 모션인 사이트라
  이건 옵션이 아니다. `aria-live` 는 스트리밍 본문이 아니라 판정문에만 건다
- 결과 공유용 URL 파라미터(`?tps=5,10,35&ttft=1.2&lang=ko&tok=o200k_base`)
- 다크/라이트, 모바일 세로 레이아웃 (이런 페이지는 폰에서 열릴 확률이 높다)

### 안 넣는다 (MVP)
- 백엔드·DB·계정·분석 스크립트 — **전부 없다.** 정적 파일이 끝이다
- 실제 모델 호출 (시뮬레이션이지 추론기가 아니다)
- 동적 OG 이미지 — 서버가 필요해지는 첫 유혹이다. 대표 프리셋 PNG 를 커밋하는 선까지

### v2 후보
- 하드웨어 프리셋(3090+Qwen 등 실측치) — **커밋된 JSON**으로. API 만들지 마라
- ja/zh 읽기 속도 기준선 (밀도는 이미 실측했다. 막힌 것은 출처뿐 — `data/reading-speed-sources.json`)
- 언어 추가

## 4. 기술 결정

### 4-1. 원본 참고 — ✅ 확인 완료 (2026-09-01): **포크 금지, 신규 작성**
`jimmyboudoux/token-speed-visualizer` 에 **LICENSE 파일도 라이선스 표기도 없다.**
미표기는 "자유"가 아니라 **저작권 전부 유보**다. v1 이 정한 대로 코드를 가져오지 않고
구조만 참고해 새로 짠다. 어차피 수백 줄이고, OSS 레퍼런스가 목표라면 출처가 깨끗한 편이 낫다.

참고할 구조(아이디어 수준, 코드 아님): 벽시계 기준 타이밍, 레인 병렬 재생, 의존성 0.

### 4-2. 토큰화 — 근사가 아니라 **실제 토크나이저** (v1 뒤집음, 2026-09-01)

v1 은 "정확 토크나이저는 wasm + vocab 수 MB라 과하다"고 판단했다. **전제가 틀렸다:**
- [`gpt-tokenizer`](https://github.com/niieani/gpt-tokenizer) 는 wasm 이 아니라 **순수 JS**,
  런타임 의존성 0, **MIT**
- o200k_base BPE 데이터 2.4MB raw → **gzip 1.0MB**. Workers 는 brotli 로 더 줄인다
- 리포에 vendoring 하면 **외부 요청 0 제약이 그대로 유지된다**

⇒ **2단 구조**:
1. 초기 로드 — 커밋된 실측 계수(`data/token-density.json`). 즉시 반응, 추가 다운로드 0
2. 「정확히 세기」/모델 변경 — 그때 토크나이저를 lazy-load 해서 실제 인코딩

근거: 이 제품의 신뢰성 전부가 밀도 축 하나에 걸려 있다. "근사치입니다" 각주를 단 사이트는
인용되지 않는다. 레퍼런스가 목표면 정확도가 곧 제품이다.

여전히 유효한 v1 원칙 — **화면에 근거를 적는다**: 기준 토크나이저·측정일·표본 크기.
숨은 근사는 거짓말이 된다.

**읽기 속도도 같은 규율** — 출처 없는 기본값을 넣지 않는다. ja/zh 는 신뢰할 출처를 못 찾았으므로
**기준선 없이 나간다**(`data/reading-speed-sources.json` 에 이유를 적어 뒀다). 지어낸 기본값은
기준선을 비우는 것보다 나쁘다. 기준선이 이 제품의 전부이기 때문이다.

### 4-3. 스택
바닐라 HTML/CSS/JS. 빌드 스텝 없음, 런타임 의존성 0, 외부 요청 0(폰트 CDN도 쓰지 마라 — CSP 깨끗하게).
프레임워크를 넣고 싶어지면 그건 범위가 샌 신호다.

## 5. 호스팅 판단 — **결론: 자체 하드웨어에 올리지 않는다**

| 후보 | 판정 | 근거 |
|---|---|---|
| **Cloudflare Workers (Static Assets)** | ✅ **채택** (v2 개정, 2026-09-01) | 원칙은 v1 그대로다 — *사용자가 기다리는 경로에 자체 하드웨어를 넣지 않는다*. **타깃만 Pages → Workers 로 바꾼다**: 2026 현재 Cloudflare 자신이 신규 프로젝트는 Workers 로 시작하라고 명시했고, 정적 자산·커스텀 도메인은 기능 동등이며 신규 기능은 Workers 에만 들어간다. 지금 Pages 로 가면 마이그레이션이 예약된다 |
| Cloudflare Pages | 🟡 v1 안 | 지금 시작하는 프로젝트가 고를 이유가 없다 |
| GitHub Pages | 🟡 차선 | 도메인 안 붙이고 던져볼 거면 더 가볍다 |
| 자체 서버 + 도커 + 터널 | ❌ | 정적 파일 하나에 컨테이너·ingress·유닛을 붙이는 건 순수 운영 부채다 |

- **도커는 어디에도 안 쓴다.** 개발 중 미리보기는 `python3 -m http.server 8000` 이면 끝이다.
- Workers 를 고르되 **서버 코드를 쓰지 않는다.** 정적 자산만 서빙한다 — 동적 OG·라이브 벤치 API 같은
  유혹이 생기면 그건 범위가 새는 신호다(§3 "안 넣는다").
- 나중에 진짜로 서버가 필요해지면 그때 자체 하드웨어를 꺼낸다. 그 경우에도 프론트는 Workers,
  데이터는 커밋된 JSON 이면 여전히 서버가 안 필요하다.

## 7. 착수 순서

1. ✅ 이 문서를 읽고 범위를 확인한다
2. ✅ `token-speed-visualizer` LICENSE 확인 → **신규 작성 확정** (§4-1)
3. ✅ 토큰 밀도 실측 + 재현 하네스 → [`docs/token-density.md`](token-density.md), `tools/`, `corpus/`
4. ✅ 읽기 속도 출처 확정 + tok/s 환산 → [`docs/reading-speed.md`](reading-speed.md)
5. ✅ 실측 결과로 제품 정의 개정 → 이 문서 §2-3 · §2-4
6. ✅ **단일 페이지 MVP 구현** (§3) — 3~5레인 + TTFT + 읽기속도 기준선 + 자기속도 측정 + ko/en +
   토크나이저 6종 + 정확 토크나이저 lazy-load + `prefers-reduced-motion` 정적 타임라인 + URL 상태
7. ✅ OSS 골격 — `LICENSE`(MIT) · `LICENSES.md` · `CONTRIBUTING.md` · `CODE_OF_CONDUCT.md` ·
   `AGENTS.md` · `_headers`(CSP) · `tests/`(node:test 17건) · `tools/check-site.mjs`(불변식) ·
   `tools/check-a11y.mjs`(axe 4상태) · GitHub Actions 3잡
8. 🟡 **시연 자료 준비 완료 — 피드백 대기.** `tools/capture.mjs` 로 실제 페이지를 찍어
   `docs/screenshots/` 에 커밋했고(라이트·다크/영문·모바일 390px·모션 줄이기), README 상단에 걸었다.
   OG 카드(`assets/og.png`)도 전용 페이지 `tools/og-card.html` 에서 생성한다 — §3 "동적 OG 없음, 커밋된 PNG까지" 그대로.
   직접 만져 볼 때는 리포 루트에서 `python3 -m http.server 8000`
9. ⬜ 공개 여부 결재 요청 (§6 — 라이선스 확정 포함)

**배포 시 잊지 말 것** (2번 결재가 나면): ① `index.html` 의 `og:image` 를 절대 URL 로 박는다
(현재는 도메인 미결이라 상대 경로 — Facebook 은 절대 URL 을 요구한다) ② Workers 정적 자산에서
`tools/`·`tests/`·`corpus/` 를 제외한다.
